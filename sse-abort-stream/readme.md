## 如何运行

在本目录执行：

```bash
npm start
```

浏览器打开 http://localhost:3790

这个 demo 没有调用任何外部模型。回答是服务端写死的 48 个字，每个字间隔 100 毫秒吐出，用来演示客户端断开之后，生成停不停。

## 期望看到什么

1. 点「会停止的实现」，等几个字出来再点「停止」：回答区立刻停住。日志出现「客户端已断开，停止生成」，之后不再有新字。
2. 点「断开后继续生成」，再点「停止」：回答区同样停住，但日志继续出现「客户端已断开，仍在生成：某字」，直到剩余文字生成完，并出现「错误实现仍把剩余内容生成完了」。

## 分析

回答正在逐字推出来，用户点「停止」，页面上的字立刻停住。点「会停止的实现」时，日志打出「客户端已断开，停止生成」，后面不再有新字。点「断开后继续生成」再点停止，页面同样停住，日志却还在逐字写「仍在生成」，直到这段文案跑完。

结论：前端 `abort()` 只断开浏览器这条连接。服务端发现连接提前关闭并清掉定时器，生成才会停。只停页面渲染，计算还在继续。

停止按钮只取消这次读取。

```js
// index.html
stopButton.onclick = () => controller?.abort();
```

正确实现听响应的 `close`。还没 `end` 就关闭，说明客户端提前走了。`stopOnClose` 为真时清掉定时器，日志是「客户端已断开，停止生成」。

```js
// server.mjs
res.on("close", () => {
  if (!res.writableEnded) clientGone = true;
});

const timer = setInterval(() => {
  if (clientGone && stopOnClose) {
    clearInterval(timer);
    pushLog("客户端已断开，停止生成");
    return;
  }
```

错误实现把 `stopOnClose` 设成 false。断开后仍取出下一个字，只打日志。日志会一直到「错误实现仍把剩余内容生成完了」。页面停了，不代表这段生成停了。
