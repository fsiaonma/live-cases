# 技术点

每次交付一个能当场跑、能对着屏幕讲的技术点。一个案例只集中一个问题、一个场景。拍视频可以用，直播也可以用。不要只写文档。

## 执行清单

按顺序做，不要跳过：

1. **确认技术点**。先核对已有案例，遵守「不重复技术点」。一个案例只有一个问题。两个问号、两套互不依赖的现象，拆成两个案例。用户指定了就用指定的。用户让你决定时，优先从未做过的 AI 全栈面试常考点里选一个。用户既没指定、也没让你决定时，先问，不要自己挑题目。
2. **建文件夹**。在当前工作区根目录，文件夹名就是技术点。可执行文件放在这个文件夹根目录，不要再套 `demo/`，不要写案例级 `readme.md`。
3. **决定运行时**。只加这个技术点演示所必需的前端、后端、数据库。
4. **追加根目录 `question.md`**。补上这一题的问题、关联 case、答案。不要在案例文件夹里再放 `question.md`。
5. **写可执行文件**。放在案例文件夹根目录。观众能在屏幕上看出差异。遵守「极简代码」。
6. **跑通**。从工作区根目录执行命令，确认成功后再回复。涉及页面的，用浏览器点一遍主路径。
7. **回复**。路径、技术栈取舍、运行命令、一句开场白。

## 选题

尽量做 AI 全栈面试题：模型调用、流式输出、工具调用、RAG、上下文、提示词、评测、权限，这些要前后端放在一起才能讲清的点。纯语言题、纯 CSS 题只有用户明确指定时才做。

需要调模型时，用工作区根目录 `.env` + `config.js` 的 `loadConfig`，不要在案例里再写一份读配置。讲协议、工具调用、检索且不必真连模型时，仍可用固定文案或本地桩；桩模拟了哪一段，在回复里一句话说明即可。

## 文件夹

- 位置：工作区根目录。用户指定了路径就用指定路径。
- 名字：技术点本身，短、可朗读。用小写英文 kebab-case。例如「Redis 分布式锁」→ `redis-distributed-lock`。
- 不要加 `case-`、`demo-`、日期、序号。不要建 `demo` 子目录。
- 案例文件夹只放可执行文件（如 `demo.js`、`server.mjs`、`index.html`）。不要 `readme.md`，不要案例级 `package.json` / `package-lock.json`，不要案例级 `.env` / `config.local.js`。
- 问题与答案只写在工作区根目录的 `question.md`。
- 目录已存在：停下来问，不要覆盖。

## 工作区根目录共用

这些文件放在工作区根目录，各案例共用，不要复制进案例文件夹：

| 文件 | 作用 |
|---|---|
| `package.json` | 仅 `"private": true` 与 `"type": "module"`。不要写 `scripts.start` / `scripts.console` |
| `.env` | 真实 LLM 配置：`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`。已被 `.gitignore` 忽略 |
| `.env.example` | 无密钥的模板，可进 git |
| `.gitignore` | 至少包含 `.env` |
| `config.js` | 导出 `loadConfig()`，读根目录 `.env`，返回 `{ apiKey, model, url }` |

案例里这样引用：

```js
import { loadConfig } from "../config.js";
```

从工作区根目录启动，不要 `cd` 进案例再 `npm start`：

```bash
node chat-history-replay/server.mjs
node chat-history-replay/demo.js
```

## 不重复技术点

选题前先看工作区根目录的 `question.md`，以及根目录下已有的案例文件夹。新案例不得与已有技术点相同，也不要换成同义说法再做一遍。例如已有 `microtask-macrotask`，就不要再做「事件循环任务队列」。

用户点名的技术点已经做过：说出已有路径，然后停下。用户让你决定题目：优先从未做过的 AI 全栈面试常考点里选一个。

## question.md

只在工作区根目录放一份，所有案例合并在这一个文件里。全文中文。一条案例一块，新题接在文件末尾：

```markdown
# 问题：一句问题？

#### 关联 case：folder-name

答案：面试最佳回答。

# 问题：另一句问题？

#### 关联 case：another-folder

答案：面试最佳回答。
```

- **问题**：一级标题写成 `# 问题：一句问题？`。冒号后面是整句问题。只问一个问题，一个问号。不要写「请谈谈 xxx」。不要把第二个技术点接在后面。
- **关联 case**：`#### 关联 case：` 后面写案例文件夹名，相对工作区根目录。
- **答案**：这一题的面试最佳回答。第一人称口述稿，大约 30–45 秒，只回答这一个问题。写成一段，不要贴代码，不要分条。按这三句收住：
  1. 结论。第一句给判断，并点出用什么标准衡量。
  2. 机制。用一个具体例子说清这次请求里发生了什么。
  3. 边界。哪一种做法会让页面看起来对、模型其实没做到。取舍用一句话带过，不要再展开。

不要写「我分三层说」「第一层是」。不要把同一件事换说法重复。不要写「如上所述」「详见代码」。不要用「然后」把句子串成流水账。不要再开另一个技术点。

## 极简代码

这是直播/拍视频对着讲的 demo，不是生产项目。

- **只留主路径**。不要 `!config.apiKey`、空值校验、404/400 分支、try/catch 回滚、busy 锁、按钮禁用、错误气泡等边缘判断。配置或请求失败就让它自然报错。
- **函数名顾名思义**。直播要专门讲的对比，拆成两个能念出来的函数，例如 `submitCurrent` / `submitWithHistory`，`requestLLM`。不要用含糊的 `complete`、`handle`、`process`。
- **对比靠改一行**。需要「问题 vs 解决方案」时，优先让讲解者改调用那一行；页面若保留两个按钮，按钮只负责选调哪个函数，不要再堆命令系统（`/history`、`/current` 等）。
- **行级注释**。只给对着屏幕要念的关键行写短注释；注释说「这一行在干什么」，不要写说明书。
- **共用逻辑上收**。读 `.env`、拼模型地址只放根目录 `config.js`。案例文件里不要再实现一遍 `loadConfig`。
- **不要无用文件**。没用到的 `config.local.js`、案例级 `.env`、案例级 `package.json`、`readme.md` 都不要留。

## 运行时取舍

从工作区根目录一条 `node 案例/入口` 跑起来。下表里的脚本、页面、工程、数据库文件都放在案例文件夹根目录，不引入该技术点用不到的层。

| 技术点需要 | 用什么 | 不用什么 |
|---|---|---|
| 只讲语言、算法、并发语义 | 单文件脚本。JS 用 `demo.js`（根目录 `type: module`）或 `.mjs` | 前端、后端、数据库、框架 |
| 只讲浏览器、CSS、DOM | 单个 `index.html`，浏览器直接打开 | 构建工具、后端、数据库 |
| 框架行为（React/Vue 的渲染、hooks、响应式） | 该框架的最小工程 | 后端、数据库，除非题目本身跨到接口 |
| 只讲 HTTP、中间件、协议 | Node 内置 `http`，一个 `server.mjs` | Web 框架、前端、数据库 |
| 题目就是某个框架 | 用那个框架的最小可运行示例 | 再套一层无关框架 |
| 要持久化、事务、索引、SQL | 案例目录里的 SQLite 文件 + 必要时一个小后端 | Docker、远程数据库、独立前端 |
| 观众必须同时看到页面和接口 | `index.html` + `server.mjs`；需要控制台对照时再加 `demo.js` | 为了「像个项目」而加的层 |
| 要调真实 LLM | 根目录 `.env` + `import { loadConfig } from "../config.js"` | 案例内再写读配置、硬编码 key |

两套结果要能对比：错误现象和正确现象、或改前和改后。输出用中文，方便对着屏幕讲，拍视频时也能看清。

依赖只写这个案例实际用到的。不要为案例单独建 `package.json`；共用根目录那一份即可。

## 跑通

- 脚本：从工作区根目录运行入口，确认退出码为 0，输出里能看出对比。
- 服务：`node 案例/server.mjs` 后请求关键路径，确认状态码和正文。
- 页面：浏览器打开，走通主交互（点击、输入、提交），不要只看截图。
- 数据库：确认库文件在案例目录内生成，查询结果和现象一致。

跑不通就改，不要把失败的案例交给用户。

## 回复用户

四件事，按这个顺序：

1. 案例路径，以及它在根目录 `question.md` 里对应的问题。
2. 用了哪些层（前端 / 后端 / 数据库），以及为什么少了某一层。
3. 从工作区根目录启动的命令（例如 `node folder/server.mjs`）。
4. 一句 20 秒能说完的开场白，直接说问题，不要铺垫「今天我们来学习」。拍视频、直播都能用这句开头。
